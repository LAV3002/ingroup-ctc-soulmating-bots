# ingroup-ctc-soulmating-bots (RegaBot)

В репозитории два независимых Telegram-бота для ивента «SoulMating»:

- **RegaBot** — поэтапная регистрация по столам, выбор симпатий, расчёт взаимных метчей (см. ниже). ТЗ — `tz/regabot.tz`.
- **DatingBot** — анкета + небольшой тест, подбор метчей по сходству ответов с фильтром по полу/ориентации (см. раздел в конце). ТЗ — `tz/datingbot.tz`.

Каждый бот запускается отдельным процессом со своим токеном и файлом персистентности.

Telegram-бот для поэтапного ивента «SoulMating»: регистрация участников, выбор симпатий, расчёт взаимных метчей и рассылка контактов парам. Требования — в `regabot.tz`.

**Два независимых стола** (`converse`, `art`) — у каждого своё состояние (этап/регистрации/симпатии), матчинг происходит строго внутри одного стола. Администратор назначается на один или несколько столов и управляет активным столом через `/use`. Участник может играть в обоих столах независимо. У стола может быть несколько сессий подряд — каждая новая сессия начинается командой `/first` и использует новые номера бейджей.

## Возможности

- **`/use <стол>`** (админ) — выбрать активный стол из назначенных; все команды ниже действуют на него.
- **`/start`** (участник) — приветствие + список команд и статус (какие столы открыты, где уже зарегистрирован).
- **`/reg_for_table [стол]`** (участник) — регистрация на текущую сессию: при первом обращении — имя → «Поделиться контактом» → стол → номер бейджа; в дальнейшем имя/контакт не переспрашиваются. Можно играть в нескольких столах.
- **Этап 1 (`/first`, админ)** — начать новую сессию: сбросить активный стол и открыть регистрацию (новые бейджи).
- **Этап 2 (`/second`)** — бот уведомляет участников активного стола; те через `/sympathy [стол]` указывают до 3 человек с приоритетом (1 — самый интересен). Если участник в обоих столах — нужно указать стол аргументом.
- **Этап 3 (`/third`)** — считаются взаимные симпатии внутри стола, админу приходит список пар + сводка.
- **`/love`** — однократная рассылка участникам контактов их взаимного метча + идей для первой встречи. `/love_force` — повторно.
- **`/reset`** — сбросить активный стол. **`/help`** — справка.

## Конфигурация

1. Скопируйте `.env.example` в `.env`.
2. Впишите `TELEGRAM_BOT_TOKEN` (от [@BotFather](https://t.me/BotFather)).
3. Впишите `ADMIN_TABLES` — назначение админов по столам в формате `user_id:тег1,тег2;...` (свой user ID узнайте у [@userinfobot](https://t.me/userinfobot)). Пример: `11111111:converse;22222222:art;33333333:converse,art`.
4. При желании отредактируйте `TABLE_TAGS` в `config.py` и идеи для встречи в `meeting_ideas.txt` (по тегу стола).

## Запуск

```bash
python bot.py
```

Состояние (по каждому столу: этап, регистрации, симпатии, флаг `/love`) сохраняется в `regabot_data.pickle` и переживает рестарт.

## Сценарий работы (админ, по одному столу)

1. `/use converse` — выбрать стол (из назначенных; по умолчанию первый назначенный).
2. `/first` → новая сессия: стол сброшен, регистрация открыта. Участники жмут `/start` (приветствие) и `/reg_for_table converse` (первый раз — имя+контакт, затем номер бейджа). Следующий `/first` стартует ещё одну сессию с новыми бейджами.
3. `/second` → бот уведомляет участников; они вводят `/sympathy` (или `/sympathy converse`, если играют в обоих столах).
4. `/third` → вы получаете список пар по этому столу.
5. `/love` → контакты + идеи рассылаются участникам.
6. `/reset` → сбросить этот стол. При необходимости повторить для второго стола (`/use art` …).

## Логирование

Подробные логи пишутся одновременно в консоль (INFO+) и в ротируемый файл `logs/regabot.log` (DEBUG). Настраивается через `.env`: `LOG_LEVEL`, `LOG_FILE`, `LOG_MAX_BYTES`, `LOG_BACKUP_COUNT`.

В лог намеренно **не попадают** имя, `@username` и телефон участника (PII); пишутся только `badge`, `user_id`, `chat_id`, тег стола, этап и счётчики. Дополнительно срабатывает защитный фильтр: телефонные номера (с ведущим `+`) и токен бита заменяются на `[PHONE]` / `[SECRET]`. Шумные библиотеки (`telegram`, `httpx`, `APScheduler` и др.) ограничены уровнем WARNING.

## Архитектурные решения

- **python-telegram-bot v22 (async)**, `telegram.ext`.
- **Два независимых стола** — состояние каждого в `bot_data["tables"][тег]`; матчинг строго внутри одного стола; бейджи уникальны в пределах стола.
- **PicklePersistence** + именованные `ConversationHandler` (`/reg_for_table`, `/sympathy`) — состояние переживает рестарт.
- **Сессии** — каждый `/first` сбрасывает стол (= новая сессия с новыми бейджами); профиль участника (имя/телефон) хранится отдельно и не сбрасывается, поэтому повторно вводить их не нужно.
- **AIORateLimiter** — защита от флуда при массовых рассылках (`/second`, `/love`).
- Последовательная обработка апдейтов (по умолчанию) — мутации общего состояния (`bot_data`) безопасны; рассылки распараллелены через `asyncio.gather` и дозируются рейт-лимитером.
- Приоритет — ранг (меньше = лучше); «СуперМэтч» — взаимная пара, где оба поставили приоритет 1. Каждый участник получает максимум 1 метч (жадное разбиение на непересекающиеся пары).
- Администраторы назначаются на столы через `ADMIN_TABLES`; `/use` выбирает активный; команды действуют только на него и только в личке с ботом.

# DatingBot

Отдельный бот знакомств: участник заполняет и подтверждает анкету, листает совместимые профили и получает контакт при взаимном лайке. Интерфейс оформлен как строгая редакционная система: стартовый коллаж, короткие экраны, единая типографика и явная навигация.

## Команды админа (только в личке с ботом)

- `/first` — открыть приём анкет; старая сессия сбрасывается.
- `/dump` — выгрузить анкеты, количество лайков и взаимные метчи.
- `/reset` — закрыть этап и удалить данные.
- `/help` — показать справку.

Порядок: `/first` → анкеты и модерация → просмотр → `/dump` (опц.) → `/reset`.

## Команды участника

- `/start` — заполнить анкету из 7 коротких шагов.
- `/profile` — открыть свою анкету, перейти к просмотру или начать безопасное редактирование.
- `/browse` — смотреть совместимые, одобренные модератором анкеты.
- `/cancel` — закрыть черновик; сохранённая анкета не изменится.

## Анкета

Имя, пол, возраст, кого ищешь, обязательное фото, хобби и главная мечта. На каждом шаге доступны кнопки «Назад» и «Отменить». Имя ограничено 40 знаками, текстовые ответы — 240 знаками: карточки гарантированно помещаются в Telegram-подпись к фото. При редактировании старая версия остаётся активной до сохранения новой; затем обновлённая анкета снова проходит модерацию.

## Подбор метчей

- В ленту попадают только проверенные анкеты с взаимно совместимыми настройками пола и поиска.
- Реакция привязана к ID конкретной карточки, поэтому повторный быстрый тап не затрагивает следующего человека.
- При двух лайках бот сразу фиксирует метч, присылает обоим карточку партнёра, прямую кнопку Telegram и идею для первого сообщения.

## Конфигурация

В `.env` задайте (см. `.env.example`):

- `DATING_BOT_TOKEN` — токен бота от [@BotFather](https://t.me/BotFather) (если пусто, читается `TELEGRAM_BOT_TOKEN`).
- `DATING_ADMIN_IDS` — `user_id` администраторов через запятую (узнать у [@userinfobot](https://t.me/userinfobot)).
- `DATING_PERSISTENCE_FILE` — файл pickle-персистентности (по умолчанию `datingbot_data.pickle`).
- `DATING_MIN_AGE` / `DATING_MAX_AGE`, `DATING_AGE_BONUS` / `DATING_AGE_PENALTY` — параметры подбора.
- `DATING_LOG_FILE` / `DATING_LOG_LEVEL` — логирование.

## Запуск

```bash
python dating_bot.py
```

Стартовый арт лежит в `datingbot/assets/soulmating-onboarding.png` и включается в пакет через `setuptools`. Если файл или отправка недоступны, бот автоматически показывает текстовый вариант.

## Архитектура

- Пакет `datingbot/` полностью независим от `regabot/` (свой `config.py`, `logging_setup.py`, `filters.py`, `state.py`).
- `python-telegram-bot v22 (async)`, `PicklePersistence`, именованный `ConversationHandler` (`dating_reg`), `AIORateLimiter`.
- Состояние в `bot_data`: этап, профили, свайпы, взаимные метчи и ссылки на карточки модерации.
- Логирование — ротируемый файл `logs/datingbot.log` + консоль; PII (имя, `@username`, телефон) в логи не пишется, телефоны и токен маскируются.
